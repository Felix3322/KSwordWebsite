02 / AUTOMATION

MCP 与 CLI 自动化入口

主程序已接入通用 Qt 对象桥，经同机命名管道连接独立 stdio sidecar。可发现页面与惰性子页，读取控件、表格和文本，执行受支持的原生动作并查询回执。普通复选框可显式设置布尔状态，同值设置不会反向切换；自绘专业控件仍需要专用适配。对象生命周期、表格模型代次与业务完成状态分别核对，派发成功不能替代结果回读。

顶部“设置 → MCP”提供本次启停、自动启动偏好、客户端配置预览和有界操作日志。自动启动偏好默认关闭，--mcp 是单次启用入口。外部 sidecar 与安装指南在 KSwordDEV/MCP；调用时启动主程序须显式选择策略，管理员启动由用户批准 Windows UAC。安装、工具发现、当前客户端加载和 GUI 连接分别验证，不自动改写其他 MCP 配置或重启已有主程序。

KswordCLI 的 R3 命令覆盖进程、网络、文件、注册表、服务、启动项、窗口与安全证据等，可输出 UTF-8 文本或 JSON，并保留 partial、unsupported、unavailable。MCP 可通过明确的 CLI 路径独立于 GUI 运行；status/help 只读，任意 CLI 命令及 GUI 修改动作要求 confirmed=true，原生命令所需确认仍保留。

system ioctl call 通过现有 ArkDriverClient 向固定 KSword 控制设备发送一次原始请求，要求 --confirm，输入和输出各限 1 MiB。它沿用调用者权限，不自动加载驱动、提权或重试。传输成功与协议解析、驱动业务状态分别判断。

03 / REPORTS

复杂报告与 PEB 工作区

进程详情的 Process Detail Evidence“结构报告”保留 Domain → Type → Field → 属性 层级，分区摘要和工具动作固定，子组折叠，字段属性及长文本在行内展开。正文按可见行绘制，避免为每个字段堆叠控件；搜索覆盖折叠后代与完整原值，清空后恢复阅读位置。复制全部与导出使用同一份规范文档，不受当前折叠或搜索过滤截断，生产者自身的未加载/截断状态继续保留。

“进程 → 进程详细信息 → PEB”恢复参数与结果并列的共享工作区：参数独立滚动、执行动作固定，摘要和只读说明正常首显；窄窗切换为上下布局。惰性字段投影与线程详情继续保留控件身份和搜索、复制、导出语义，布局调整未扩大 PEB 写入或采样权限。

已有真实主程序的深浅主题、约 800px 窄窗和搜索状态检查记录。结构报告现场覆盖静态目录与错误态，驱动采样成功、复制/导出的完整端到端、DPI 和全部背景模式仍有未验收项；独立线程采样及其它旧报告源也不能视为已全部迁移。

04 / WORKBENCHES

注册表与权限工作台

注册表已扩展为类型化工作台：多位置标签、收藏与历史、32/64 位视图、按名称/类型/数据搜索、完整值编辑及暂存清单。应用暂存前核对读取基线，修改后按实际通道回读；提供原始子树备份、受支持的上次提交恢复、键权限和离线 Hive 工作副本。暂存不是已经写入，列表摘要和不完整读取不会冒充完整值。

权限页覆盖用户/组管理、LSA 用户权限分配、令牌对比、访问诊断、登录会话与进程关联、指定身份启动和手动权限快照。账号以 SID、进程以 PID 与创建时间关联；直接策略分配、实际令牌和句柄打开结果分别展示。快照差异保留值类型和采集错误，缺失证据标为无法确认，不自动还原权限。

账号、组和策略修改保留预览、确认及回读；UAC、SYSTEM/TrustedInstaller 等身份启动有各自权限要求。已保存的只读/模型回归不等于真实账号写入、策略修改或提升启动验收。

05 / CKS RESEARCH

CKS 管理与免重置研究

“杂项 → CKS 管理”分为“微软现行流程”“SSDE 实验流程”“免重置研究”三页，共用当前系统证据与结果区。研究页整理精确组件身份、登记链和验证模板，历史研究样本与当前查询分开。

免重置首次启用仍是未验证研究。

启动前重新建立登记与保留应用的修复安装是两条独立候选，尚无成功流程验收。既有关闭登记不会因普通策略刷新自动成为首次启用；许可值、策略文件或 CiTool 成功不足以证明目标驱动已获信任。需要核验实际策略/签名、驱动加载、重启和更新保持，不能将静态研究宣传为已可用功能。

06 / MEMORY

统一内存编辑器与 Intel 汇编

主程序的 R3/R0/R-1、DDMA、影子页、Hook 向导、内核反汇编与转储内存入口共用快照组件。Hex、文本、反汇编和对比使用同一份字节；橙色表示待提交修改，青色表示两次读取的变化，提供本地撤销/重做。

x86/x64 Intel 汇编支持多行、局部标签、实际地址分支与 RIP 相对寻址。数字默认十六进制，十进制用 0d；编译和预览仅暂存字节，所属页面显式应用，写前核对原字节、写后检查实际回读。它不实现 CE Auto Assembler 脚本。只读入口不会因可查看汇编而获得写权限。

R3/R0 区域 Dump

主导航内存页及进程详情的内存区域列表可分别选择“R3导出此区域Dump…”或“R0导出此区域Dump…”，输出与区域等长的原始 .bin，不等同整进程 dump 或 minidump。导出冻结区域与进程身份，逐块检查完整读取，短读、取消或失败不发布半个文件；后端由所选动作固定，不自动回退。真实 R3 GUI 导出已有受控字节与哈希核验，R0 实读尚未加载驱动验收；运行进程的分块读取不保证同一时刻的一致性快照。

07 / MONITORING

API、ETW、Syscall 与回调监控

API Monitor 已有独立 x86/x64 Agent、641 项共享 JSON 定义、主程序集中跨位数注入与子进程会话服务。API 覆盖页展示实际安装、等待、排除与失败；异步 I/O 区分提交、完成和取消。Raw 只记录入口，直接 syscall、任意 COM 和监控前调用不保证覆盖；TSV 只导出当前可见行，队列丢失单独计数。

ETW 按载荷关联进程与线程，保留原始事件头身份；数组、结构和 TraceLogging schema 按布局解析，未知或截断留证据缺口。Syscall 以原始 QPC、CPU 和 StackWalk 关联，兼容桩形态仅作为证据，不能由单个 syscall 字节或 RWX 判定恶意/工具版本。

内核回调监控使用独立 Control/Query/Read 与多消费者游标；暂停冻结 UI 提交，后台继续有界读取。它观察 Ksword 运行时回调事件，区别于列出系统注册回调和 AskUser 拦截规则。

08 / FILES

文件详情与 R0 删除

文件详情提供单文件/批量元数据暂存，底部“保存全部修改”统一复核文件身份、备份、写入与回读。基础时间/属性、ADS、EA、权限、重解析点、文件系统属性和 PE 资源各有边界；高风险修改强制备份。签名页突出 WinVerifyTrust 信任结果，字符串按条件扫描全文件，Hex 支持按偏移分页跳转。

R0 删除有分阶段回执。IRP 预设采用托管打开并向基础文件系统提交，普通/忽略共享/强制方式保留不同风险与确认；强制清空映像/缓存 section 成员不能保证活动映射一致性。关闭句柄后确认路径不存在才算完成，构建或模拟测试不能证明实机删除安全。

文件右键菜单隐藏不可用动作和空子菜单，单选 .exe 可按令牌能力选择 System、TrustedInstaller、管理员或普通用户启动。启动保持交互式 Session 与目标用户环境，不以身份失败后继承更高权限替代。普通用户路径与菜单回归已通过，管理员/System/TI 的成功启动实机探针在未提升的验收宿主上未执行。

09 / KERNEL

回调注销与内核知识中心

V3 回调清单保留注册变体、来源、身份与可信状态。Object 使用真实 RegistrationHandle，Registry 使用 Cookie；EX 请求在驱动重新枚举核对，公开 API 调用后复核目标。新增配对注销类别保留 candidate，不宣称所有版本已验证；实验 unlink 菜单已移除，ETW/EMP 缺真实句柄的行仍不可移除。

Minifilter 子行的动作是“卸载所属过滤器”，包括全部回调和实例，过滤器可拒绝。知识中心提供 12 类 71 专题、现场证据与只读业务页路由；Available 表示链路闭环，不证明当前机器全部权限/偏移/字段可用。

10 / VIRTUALIZATION

Intel EPT 与 AMD SVM/NPT

当前代码包括 Intel 常驻、MSR bitmap、退出模拟、EPT 双视图/策略，以及 AMD SVM/NPT 实验后端。标题栏与 KVM Dock 共用准入，按硬件、逐 CPU 自检、电源代次、拓扑和卸载保护发布状态；未知外层与 Hyper-V/VBS 冲突不能靠开关绕过。

EPT ENFORCE 当前返回 UNIMPLEMENTED。

不能将旧 #PF 拒绝路径宣传为已完成的持久强制。WATCH_ONCE 捕获首次访问现场后放开对应页，不是所有后续写入的日志。代码执行分离视图不是普通数据冻结或通用进程隔离。

11 / NESTED

嵌套实现与验收范围

Intel 已有 vmcs12、退出反射、影子 EPT 及后代页/区域租约；支持、准备、全核 armed 和瞬时 L2 运行分别报告。AMD 已有通用 VMCB/NPT、事件协调与首故障记录，但保持实验 PARTIAL。

已保存 AMD 单核/8 核启停和 32 核短常驻证据。固定探针逐核串行往返不等于内层多核 OS 并发；完整 L2 启动已有三重故障/宿主崩溃记录与待复测候选，不能宣布完整 OS 兼容。七步拓扑演示保留的是历史 Intel/Hyper-V 示例，不覆盖 AMD 或所有外层配置。

12 / R-1

R-1 内存与目标操作

R-1 内存支持物理/虚拟读写、翻译与按 PID 定位。私有窗口不可用时读取可降级并明确报告，写不可用；快照绑定地址、CR3/PID、模式与代次。目标操作还需要正确目标身份、映射、策略与常驻状态。所有界面应检查具体回执，不能把请求成功当作目标已退出或字节已改变。

13 / DEBUGGERS

CE / x64dbg 与剪贴板保护

共享调试后端管理身份、内存、上下文、HVM 与自有资源；CE/Titan 使用真实 Windows 停止事件。执行断点可按能力走 EPT 或明确记录的 Shadow INT3 回退。隐蔽模式拒绝可见 DR/PAGE_GUARD 回退；CE 与 Titan 的数据断点范围分别维护。Shadow 代码写入要求私有/COW 页，不能等同数据 freeze。

剪贴板保护按位数选 Agent，与 API Monitor 共享 PID 租约，配置可热更新。仅收到 Hook 安装就绪才计入受保护进程；规则命中/注入成功不等于全局保护，跨用户、直接调用和受保护目标保留覆盖限制。

14 / LIGHT

Light 调查工作台

原生 Win32 x64 Light 保留二级页懒加载、实体路由、PID+创建时间与跨进程驱动租约。预先运行的驱动不由退出的 Light 误停；R3 浏览和证据在驱动不可用时继续工作。

命令框默认导航模块/实体，只有前导 ! 执行 shell。成功导出进入证据会话，可做最近两次行级 diff、JSON/TSV 与用户目录脱敏。内存历史重放成功读取的本地快照，原生编辑器未包含 Qt 主程序的汇编功能。详细进程列区分未知、预热和真实 0；I/O 速率不等同物理磁盘吞吐。

15 / UI & COMPATIBILITY

搜索、窗口控制与兼容策略

全局 UI 搜索、快照差异和主题控件统一接入主工作台。窗口输入/DWM 排序在窗口和杂项两页均可直接操作；DWM 画面顺序与原生输入顺序分开。跨 UIAccess 的 Win32k 写事务仅适配精确 win32kfull 10.0.26100.9022，回执测试不代替真实点击验收。

驱动/Launcher 的 OS build 上限已取消，仍保留最低 build 16299 与逐功能能力/偏移/布局检查。解除启动上限不增加未知系统的已验证 profile，也不保证所有功能可用。

进程设置与历史保留

齿轮按钮打开独立“进程列表设置”，集中枚举、刷新、R0 对照及后台记录选项。活动历史提供“不记录历史 / 全量留存 / 留存最近”，默认最近 50 次；减少次数立即裁剪，不记录只停止后续采样，保留已有样本。

SOS 救援桌面

运行配套 Taskbar 与主程序，用真实键盘依次输入 S O S Enter，在原桌面批准 UAC 后，于限制访问的私有 Win32 桌面启动新的管理员 KSword。顶部返回按钮或真实键盘 Ctrl+Alt+Shift+F10 恢复原桌面；原实例与未保存会话不迁移。它不是 Windows Winlogon/UAC 安全桌面，R3 无法证明虚拟 HID 或驱动级输入来源。基础切入/返回已有现场记录，锁屏、焦点干扰及各类输入仍须分别验收。见SOS 救援桌面说明。

共享页面结构与 Taskbar 总览

普通控件、表格操作条、二级详情、参数工作区和多级 Tab 逐步接入共享主题与布局，保留字段来源、专业视口、复制/导出和快照语义。近期修复包含透明主题表面、菜单/搜索状态、子页导航与圆角边界；共享规则不代表所有存量页面已完成视觉验收。

独立 Taskbar 右侧网格按钮打开真实页面总览，按主程序目录分列展示一级及嵌套页面，支持名称/路径搜索与逐层直达。可调背景模糊在系统合成不可用时保留透明导航回退；RGB 只作辅助强调。需使用匹配的 Taskbar 与主程序，实机模糊、DPI 与全部跳转效果仍按场景验收。

16 / EVIDENCE

沿证据阅读功能

实现/构建/签名/加载/GUI/硬件场景分别报告。API 真实自有进程与 offscreen 回归、调试器受控 VM、AMD 短时常驻和模拟注销各有不同范围；旧候选与新源码不能混用。未知、Partial、Truncated、丢事件、候选和 NOT_RUN 都保留在结论中。

17 / OPERATOR NOTES

使用顺序

  1. 1
    选择配套构建并先查看状态。

    记录系统、驱动、profile、目标身份与能力；Unsupported 和缺数据不能读成“没有异常”。

  2. 2
    先观察与导出，再做修改。

    内存/文件暂存不等于已写入；注销/删除/HVM 操作保留确认和恢复记录。

  3. 3
    检查实际结果与覆盖范围。

    核对回读、路径存在、后置枚举、完整 CPU 集合和丢失统计；失败或部分完成不报告整体成功。
