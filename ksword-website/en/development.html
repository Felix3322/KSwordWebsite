Commits in the last month

The GitHub API returned 653 commits from 2026-07-16 through 2026-08-16; the sections below deduplicate them into user-visible capability and safety changes.

Version boundary

5.1.4.0 is the stable release; 5.1.4.1-Alpha and 5.1.5.0-pre are prereleases. main is 171 commits ahead of 5.1.5.0-pre; do not replace one EXE or SYS inside a release package.

Use Releases when you need stable assets.

The application, KswordARK.sys, shared IOCTLs, language packs, DynData profiles, Launcher, and plugins must come from the same build chain. Mixing files can produce Unsupported states, protocol mismatches, or missing fields.

02 / KERNEL & R0

Kernel audit, dynamic offsets, and fail-closed behavior

Audit additions and expansion
  • IDT, code integrity, VBS/HVCI posture, and page protection.
  • SLAT/IOMMU, EPT/NPT, Hypervisor CPUID, and DMAR/IVRS.
  • HAL, WDF/KMDF, i8042prt, object types, special callbacks, and IoTimer.
  • System threads, work queues, descriptor tables, IOCTL decoding, and kernel disassembly.
Runtime safety
  • PDB-independent runtime signature scanning and offset fallback.
  • DynData v4 profiles and Launcher support manifests.
  • Safe reads for fallback kernel addresses to reduce DriverEntry crash risk.
  • A fail-closed physical bugcheck panel while preserving the VMware display path.

These pages remain gated by Driver Status, Capability, DynData, and target identity. A visible control does not prove that its R0 capability is ready.

03 / DUMP FORENSICS

Crash dumps now expose more attribution evidence

The dump-analysis workflow now previews triage crash context, triage data blocks, secondary dump records, captured memory, and BlackBox evidence. Together with symbol resolution, pool-tag ownership, and a crash timeline, this gives the operator a richer diagnostic record. Bugcheck display keeps explicit boundaries between physical and VMware paths.

Dump evidence is diagnostic material, not an infallible automatic verdict.

Missing, Partial, and Unsupported fields must remain visible instead of being filled with a default “normal” value.

04 / PROCESS & SECURITY

Process identity, startup chains, and attack-chain detection

Processes and threads

Process tables gain near-Task-Manager columns, custom views, target-thread message-hook visibility, module/thread/token/PEB details, and renewable process protection backed by object-manager callbacks.

Startup and loading

New checks cover DLL hijack candidates, IFEO image hijacks, hidden-startup cross-checks, and the EXIT GhostSystemDriver attack chain; startup-location coverage now reaches 187 entries.

Application control

AppLocker loading now handles unavailable modules, application-control editors and context actions were added, and global hotkeys support safe editing and deletion. Service enumeration and cleanup continue to be hardened.

05 / FORENSICS

Files, networking, and system utilities move further into R0

Files and storage
  • MFT, IRP, R0 directory parsing, and resumable scans.
  • Five-tier deletion permissions and R0/POSIX deletion backends.
  • Physical-sector reads, raw-filesystem browsing, storage, and device evidence.
Networking and system tools
  • R0 WFP packet-capture start/stop, connection management, and network diagnostics.
  • DNS, WFP firewall, HTTPS proxy recovery, and NIDS continue to be refined.
  • System time, performance monitoring, USB topology, system-bus, and context-menu tools.

06 / LIGHT

KswordARKLight gains more read-only pages and reversible controls

Light now includes network, window, system-tool, performance-bus, service, and privilege modules. It also wires packet-capture controls, PiDDB-entry deletion, physical-disk reads, and restore-or-abandon actions for driver dispatch, image, and communication records. Writes, deletes, recovery, and abandon actions remain confirmation-gated and generation-checked.

Abandon does not change kernel state, but permanently discards the recovery record.

That makes abandon more dangerous than restore; the website and the program should keep this distinction explicit.

07 / UI & RUNTIME

Large tables, taskbar behavior, and themes continue to move

Main adds adaptive table-search scopes, header sorting, frozen rows and columns, taskbar notification filtering, target-thread hook visibility, bugcheck-panel refinements, dynamic-theme and transparent-background fixes, while continuing to close lifetime issues in file-occupancy scans, asynchronous refresh, driver search, API Monitor, hardware monitoring, and shutdown.

Many of these commits are reliability fixes or internal experiments; they should not be presented as separate formal releases.

09 / OPERATOR NOTES

Minimum checks before testing main

  1. 1
    Build the complete package from one commit.

    Do not replace only the EXE, SYS, language packs, profiles, or plugins.

  2. 2
    Check Driver Status, DynData, and Capability first.

    Unsupported means that the protocol, driver, or capability is unavailable; it does not prove that the page has no data.

  3. 3
    Use authorized, rollback-capable environments for risky actions.

    System time, HVM, disk writes, driver unloads, kernel changes, process protection, and deletion require a snapshot or tested recovery path.

  4. 4
    Preserve pre-change evidence.

    Record target identity, address, owning module, configuration, and timestamps; refresh and save the post-change result.
