02 / SYSTEM TIME

System-wide acceleration, slowdown, and a calibrated clock

The Miscellaneous workspace now contains a system-time control path that changes how the system performance counter advances. It offers a compatibility mode and a guarded mode with extra validation. Guarded mode reduces some configuration risk but can still freeze or crash the system.

Control and recovery
  • System-wide acceleration or slowdown
  • Selectable factor and implementation mode
  • Two-stage risk confirmation
  • Stop and restore the original counter
Display and synchronization
  • Request a Windows Time resynchronization
  • 15-second timeout and error diagnostics
  • Show time calibrated against the current factor
  • Display system time and KSword runtime in the title bar
This is not an in-app animation-speed control.

It changes the entire system's observation of time. Network protocols, licensing, scheduled tasks, logs, anti-cheat systems, databases, and software that depends on monotonic clocks may fail. Prepare a tested recovery path first.

Related commits: ab93b7e, 5933bda, 8a4bd0d, a7127b3, and 2260e06.

03 / NETWORK

R0 network auditing now reaches WFP packet layers

The Network workspace is no longer limited to connections, endpoints, or WFP events. A new protocol incrementally reads WFP IPv4/IPv6 IP-packet-layer captures from the driver, while user mode validates response headers, row sizes, sequences, address families, TCP/UDP protocols, packet bounds, and bounded capture lengths.

Incremental packet retrieval

The client advances an afterSequence cursor instead of copying the complete history on each refresh.

Drop and cursor diagnostics

Responses distinguish truncation, cursor gaps, cursor resets, driver-side drops, and WFP unavailability.

Protocol compatibility

An older driver without the new IOCTL is reported as Unsupported. An empty table must not be interpreted as proof that the system has no traffic.

Related R0 inventories

TCP, UDP, AFD, NSI, NDIS, and WFP inventory/cross-view pages remain available to correlate packet evidence with kernel objects.

This is one of the features most sensitive to client/driver version mixing.

The packet ABI, NDIS dependencies, and diagnostics were completed across consecutive commits. A new EXE with an old SYS can produce Unsupported results, protocol-validation errors, or missing fields.

Related commits: eabec0d, bcb8386, f8710df, and 5a46b70.

04 / FORENSICS

Structured scanning, kernel baselines, raw filesystems, and controlled HVM

Scanner Dock

Background parsing covers PE, ELF, and Mach-O. The optional byte editor accepts only length-preserving changes, revalidates the source snapshot, performs an atomic replacement, and can retain a backup.

Advanced kernel forensics

Loaded-image and IDT clean baselines, descriptor-table and IOCTL decoding, kernel disassembly, system-thread and work-queue views, and broader callback/object auditing have been added.

Storage forensics

A read-only-by-default raw-filesystem browser can inspect directory entries, deleted records, and low-level storage evidence. Disk writes remain separately locked and confirmation-gated.

HVM diagnostics

A confirmation-gated VMX self-test and one-shot test guest produce VM-exit telemetry. This is an authorized-lab diagnostic path, not a general-purpose virtual machine.

These capabilities extend the existing DriverObject, DeviceObject, SSDT, hook, callback, module cross-view, Unloaded/PiDDB, PTE, and memory-evidence workflow.

Related commits: 8ce2b2a, 7ba04ed, 21cc83f, and 7ff3ee8.

05 / RUNTIME

Runtime PDB fallback, long-running diagnostics, and interaction controls

  • When packaged DynData does not match, the full and Light applications can resolve an exact runtime PDB in a serialized DbgHelp session. Results are applied only after PE/PDB identity validation succeeds.
  • Tables gain freeze controls and smooth scrolling to reduce accidental selection changes and preserve the current inspection point during large refreshes.
  • Core Audio source inspection has expanded so active audio sessions can be correlated with processes and devices.
  • The API Monitor Agent can wait for another session, detect a new session ID, and interrupt pending pipe writes, reducing failed restarts and shutdown-time crashes.
  • Disk-performance monitoring, asynchronous view snapshots, and driver search received further lifetime and race fixes; Release output also deploys the Qt runtime.
Runtime PDB is an exact fallback, not a “nearby Windows build” offset guess.

When identity or required fields do not match, dependent R0 capabilities must remain safely degraded instead of borrowing offsets across builds.

Related commits: 6943a1a, 4d7eb6a, 44b21d0, and a323cb0.

06 / HARDENING

Destructive-action confirmation and audit boundaries keep tightening

Process termination

Destructive tree and critical-target termination paths now require explicit confirmation, reducing the blast radius of a single mistaken action.

Startup and permanent deletion

Targets are revalidated immediately before execution. Machine-level startup parking, registry recovery records, and delete operations have stronger access control and recovery transactions.

Process and thread identity

Historical processes, thread actions, work-queue auditing, and asynchronous context-menu refreshes use more stable identity snapshots and close refresh/shutdown lifetime races.

Platform and kernel baselines

Loaded-image, platform-security, directory-service, callback, and hardware audits validate trust boundaries before traversing kernel-provided data.

Representative commits: c02d2e0, 8be550b, 82e6264, cfca4cc, and 7ef8370.

08 / OPERATOR NOTES

What to know before testing main

  1. 1
    Build the complete package from one commit.

    This especially applies to the main application, KswordARK.sys, shared IOCTL headers, language packs, and DynData profiles.

  2. 2
    Check Driver Status and Capability first.

    A visible control does not prove that the target IOCTL, PDB field, or kernel capability is available.

  3. 3
    Test system time, HVM, disk writes, and kernel mutation only in an authorized environment.

    Prepare a VM snapshot, recovery media, or another tested rollback path.

  4. 4
    Use Releases when you need stable assets.

    This page does not disguise main-branch development as a formal version number that does not exist.
