选哪个程序

完整版是 Qt6 界面，页面和插件功能最全；Light 用原生 Win32，绕过 Qt6 的兼容范围，适合秒开查进程；脚本调用选 KswordCLI。普通查询不必加载驱动，需要内核枚举、R0 内存或 HVM 时再连接相应后端。

安装与启动

下载发行包后完整解压 Release/，从 Launcher.exe 选择完整版或 Light。Qt DLL、platforms/qwindows.dll、profiles/ 和 languages/ 要和程序一起保留。启动时报缺 DLL 或 Qt platform plugin，先检查是否只复制了 EXE，或混用了不同包的依赖。

Launcher 启动与版本兼容 →

连接驱动

在驱动管理中加载同一发行包的 KswordARK.sys。Loaded 看驱动有没有加载，Protocol 看程序和驱动能否通信，DynData 看当前系统的私有结构偏移是否齐全，Capability 看这次实际能用哪些功能。驱动已加载，但某个页面不可用，要看该项的诊断，不能只盯着 Loaded。

符号与动态偏移

Windows 更新后，有些内核功能可能因缺少偏移而不可用。PDB/DynData 按系统模块的精确身份匹配，相近的 build 不能混用。Launcher 提示缺配置时，按提示收集兼容性报告；--launcher-check-only 只检查支持清单，不会生成报告。

连接调试器

先安装配套的 Cheat Engine 或 x64dbg/x96dbg 插件，再在 KSword 的调试器页面选后端、启动调试器并附加进程。R0/HVM 模式看日志里实际选中的机制；发生原生回退时，日志会说明。调试器保留自己的窗口，KSword 页面负责后端选项和日志。

调试器安装与后端选项 →

查看进程

双击进程打开详情，可以继续查线程起始地址、模块签名、句柄、内存区域、令牌和 PEB。怀疑列表漏报或进程被隐藏时，用可用的 R3/R0、HVM 或 DDMA 来源做 cross-view，找出哪一层能看到、哪一层看不到。对比同一实例的 PID 和创建时间，避免把进程退出、PID 复用当成隐藏。

内存编辑与区域导出

附加进程后选择读取后端、地址和长度，同一份字节可切换 Hex、反汇编、文本和差异视图。区域列表右键的“R3/R0 导出此区域 Dump”保存原始 .bin，大小等于所选区域，不是整进程 minidump。短读或取消不会留下半个新文件；运行中的内存仍可能在分块读取时变化。

内存视图与汇编语法 → 区域 Dump 格式与导出规则 →

文件管理与占用查询

文件页用双面板浏览目录；文件详情可看 PE 头、节区、签名、哈希和字符串。遇到“文件正被使用”，先查占用结果中的进程、句柄或模块映射。句柄占用和 DLL 映射是两回事：映射记录没有一个可以直接关闭的文件句柄，不能都按“关闭句柄”处理。

内核工具

在“内核 → 对象命名空间”沿目录查看对象、符号链接和目标路径；原子表也能直接查询。SSDT、内核回调等页面需要配套 R0 能力。回调清单看当前注册项和所属模块，Callback Monitor 看启动会话之后发生的事件，两者回答的问题不同。字段含义可以接着查内核知识中心。

连接与端口

查端口占用时看连接列表的 PID、本地地址和端口，再跳到进程详情；UDP 项没有 TCP 那样的连接状态。抓包页按网卡和过滤条件采集，手工请求页可改 URL、Header、Body 并查看响应。HTTPS 分析走本地代理，使用时还要处理证书和系统代理，结束后从对应入口恢复。

安装插件

插件市场提供安装入口，也可从本地目录加载；重新加载后打开对应插件页。CE、x64dbg/x96dbg 这类插件还需要调试器本体和匹配架构的适配文件，下载一个插件包并不等于已经装好宿主。

注册表与系统设置

注册表页可在树和值列表中编辑，也可用文档视图预览变更；遇到“明明存在却查不到”的键，先检查 32/64 位视图。启动项页把文件、注册表、服务、计划任务和 WMI 等入口放在同一列表，能继续定位原始项。禁用和永久删除的恢复方式不同，按具体动作的提示处理。

注册表功能与边界 → 注册表 CLI 命令 →

结束会话

监控会话用本页的停止按钮结束，HVM 常驻先从虚拟化页停止，再处理驱动卸载。关闭某个页面或主窗口不等于全局驱动服务已经卸载；是否还在运行，看驱动管理和 HVM 的实际状态。

遇到问题

启动失败先记下完整错误；某项功能不可用时，把页面显示的原因和驱动能力状态一起带上。报 Bug 最有用的是：用了哪个包、Windows build、CPU/虚拟化环境、从哪一步开始出错，以及原始错误码。能用最少几步复现，比只发“不能用”更容易定位。

启动监控

监控页可选 ETW、Syscall 或 WinAPI。按目标进程和事件类型启动，先看会话是否就绪、Hook 覆盖和丢事件计数，再看事件表。表为空时，可能是过滤条件、位数或注入状态不对。API Monitor 和剪贴板保护不能同时占用同一个进程。

详细说明 →

虚拟化工具

在“虚拟化”页检查 CPU 能力和拒绝原因，依次准备、自检、启动常驻；成功状态要看全部预期 CPU，而不只是一个已勾选的开关。Intel 走 VMX/EPT，AMD 走实验性的 SVM/NPT。AMD 的完整内层多核系统启动仍未完成验收，具体可用功能看当前能力和实验记录。

使用 Light

Light 不依赖 Qt6，适合旧系统兼容和快速打开。命令框输入 pid、tid、hwnd、file 或 reg 可直达相应对象；前导 ! 才表示执行命令。查到的结果可导出 JSON/TSV，并比较最近两次快照。需要完整版页面和插件时换回 Qt6 版。

剪贴板保护

在“杂项 → 剪贴板保护”按进程或全局配置读取、写入、枚举规则，选择允许、记录或阻止。规则要由目标进程中的 Agent Hook 执行；启动后看 Agent 是否就绪和日志中的命中记录。仅有一张驱动策略表，不代表所有访问已经被拦住。

Agent Hook 与会话规则 →

系统要求

Qt6 完整版最低为 Windows 10 1809（build 17763）x64；更早的 Windows 10 可由 Launcher 选择 Light。驱动另有最低 build 16299，能打开 Light 不等于 R0 全部可用。更新系统上的私有结构功能还要有匹配的 DynData，不能只按 Windows 版本号判断。

接入 MCP

打开“设置 → MCP”启用对象桥，复制安装提示词或客户端配置。只用 CLI 时不需要启动 GUI；使用 GUI 时可以连接已运行实例，或明确选择自动启动。默认按程序完整路径找实例，比固定 PID 省去每次重启后改配置。安装完用 GUI 的 hello/pages/snapshot 或 CLI 的 status/help 检查实际连接。

MCP 工具与配置 → MCP 安装步骤 →

使用命令行

运行 KswordCLI help 找命令和参数，再按进程、文件、注册表等分类查手册。脚本和 MCP 都可调用 CLI，不必先打开图形界面。原始 IOCTL 是单独的低层入口，需要明确确认，输入、输出各限 1 MiB；日常查询优先用已有命令。

报告与权限工作台

进程详情的结构报告可按类型和字段查偏移、字段值，搜索、复制、导出使用同一份文档。PDB 字段目录说明结构怎么排布，实时字段值还要看是否采集成功。权限工作台用于查账号、组成员、令牌和访问权限，也能比较两次快照，找出权限发生了什么变化。

查找页面

记不清功能在哪时，直接用标题栏搜索页面名、路径或控件文字，点结果跳转并高亮。Taskbar 右侧的网格按钮打开页面总览，输入名称或路径，Enter 跳转、Esc 收起。标题栏切到 CMD 模式后才会执行命令，搜索模式不会把输入当命令运行。

CKS 管理

“杂项 → CKS 管理”可查当前状态并进入登记流程。第三个子页整理的是免重置研究，不是已可用的免重置方案：启动时重新登记和修复安装两条候选目前都未验证成功。需要了解具体限制时，直接看研究记录中的系统 build 和证据。
